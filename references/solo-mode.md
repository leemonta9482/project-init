# 02 · 개인 모드 (혼자 할 때)

> 전제: `00_방법론_원리.md`. 이 문서는 **혼자 진행할 때** 무엇을 끄고 무엇을 남기는지 다룹니다.
> 핵심: **사람 경계는 지우되, 구조 경계와 자동 게이트는 남긴다.**

혼자가 되었다고 규율을 버리지 않는다 — 이것이 개인 모드의 전부입니다.

---

## 1. 무엇을 끄는가 — 사람에 의존하던 규칙

| 규칙 | 이유 | 처리 |
|------|------|------|
| CODEOWNERS 경로별 배정 | 소유자가 한 명뿐 → 무동작 | 한 줄로 축약 (`* {{OWNER_HANDLE}}`) |
| 동료 리뷰 승인 | 리뷰할 상대가 없음 | self-merge |
| 영역 간 협의 | 협의 상대 없음 | (계약 문서는 유지) |

→ **사회적 경계는 자동으로 무의미해진다.** 미련 없이 축약한다.

---

## 2. 무엇을 남기는가 — 구조·자동화에 걸린 규칙

여기가 핵심. 사람이 줄어도 아래는 **그대로 살린다.**

| 규칙 | 협업 | 개인 | 왜 남기나 |
|------|:---:|:---:|-----------|
| 변경 제안(MR/PR) 경유 | 필수 | **유지** | CI 실행점 + 변경 이유 기록 + 기본 브랜치 보호 |
| CI 다층 게이트 | 필수 | **유지** | 리뷰어 대신 실수를 잡음 |
| 고비용 계층 보호 | 승인 게이트 | **자기 규율로 유지** | 흔들리면 품질이 무너짐(사람 수 무관) |
| 계약 lockstep | 필수 | **유지** | 배포 안전은 팀 규모와 무관 |
| 커밋·TDD 규율 | 필수 | **유지** | 미래의 자신을 위한 것 |
| 파괴적 명령 금지 | 필수 | **유지** | 혼자일수록 잡아줄 사람이 없어 더 중요 |

> 사라진 건 *사람 의존* 규칙뿐. *구조·자동화* 규칙은 전부 생존.

---

## 3. self-merge인데 왜 변경 제안(MR/PR)을 유지하나

가장 반직관적인 규칙. "혼자인데 왜 PR을?"

변경 제안은 **리뷰용만이 아니다.** 네 가지를 동시에 한다:

| 기능 | 협업 | 개인 |
|------|:---:|:---:|
| 동료 리뷰 | ✅ | ❌ 사라짐 |
| **CI 파이프라인 실행 지점** | ✅ | ✅ **유지** |
| **변경 이유의 영구 기록** | ✅ | ✅ **유지** |
| **기본 브랜치 보호 우회 경로** | ✅ | ✅ **유지** (직접 push 불가) |

→ 리뷰 기능만 빠졌을 뿐, 나머지 3기능이 여전히 유효하므로 **변경 제안은 유지**한다.

---

## 4. 고비용 계층 보호 (개인 모드의 중심 규율)

협업 때는 승인 게이트였지만, 지금은 **자기 규율**로 남는 경로.
"함부로 안 바꾼다"는 원칙은 그대로, 강제 주체만 리뷰어 → 자신으로 바뀜.

`{{PROTECTED_LAYERS}}` 에 해당하는 것들 — 흔한 예:

| 계층 | 왜 고비용인가 | 바꿀 때 |
|------|--------------|---------|
| 디자인 시스템 / 공유 UI | 흔들리면 화면마다 골격 재발명 → 일관성 붕괴 | 기준 디자인 대조 후 정해진 절차로 |
| 공유 커널 / 코어 유틸 | 전 모듈이 의존 → 파급 큼 | 계약 유지 확인 후 |
| 공개 API 계약 | 외부/타 모듈이 의존 | 버전·BREAKING 관리 |
| DB 스키마 | 데이터 손실·마이그레이션 위험 | lockstep(원리 5) |

### 왜 혼자여도 지키나

> 승인 게이트로서의 의미는 없어졌지만 **이유는 그대로다.**
> 혼자여도 이 계층을 즉흥적으로 늘리면 품질이 다시 무너진다.

---

## 5. 개인 규율의 원리 — 왜 혼자여도 규칙을 지키나

### (a) 미래의 자신을 위한 감사 추적
커밋 메시지·변경 제안 설명·spec/plan은 **몇 달 뒤의 자신**이 읽는 문서.
"왜 이렇게 짰지?"를 그때 재발명하지 않도록 지금 기록한다.

### (b) 자동화가 기억을 대신한다
사람 리뷰어가 없어도 **CI·훅·lockstep이 실수를 잡는다.**
규율을 자동화에 위임했기에, 규율을 *기억할* 필요 없이 *실행하면* 된다.

### (c) 파괴적 명령 금지는 오히려 강화
`force push`·`reset --hard`·볼륨 삭제 금지는 협업 여부와 무관.
혼자일수록 되돌려줄 사람이 없어 더 중요하다.

### (d) 계획 우선도 유지
혼자여도 spec → plan → 구현 순서를 지킬 수 있다(trivial 예외 동일).
자기 자신에게 작업지시서를 쓰는 셈 → 구현 중 방향 이탈 방지.

---

## 6. 개인 모드 요약

| 항목 | 방식 |
|------|------|
| 경계 | 계층 사이 (고비용 계층을 자기 규율로 보호) |
| 경계 강제 | 자기 규율 + CI 게이트 (CODEOWNERS는 `* {{OWNER_HANDLE}}`로 무동작) |
| 승인 게이트 | self-merge |
| 변경 제안 | **유지** — CI 실행점 + 변경 기록 + 기본 브랜치 보호 |
| 끈 것 | 사람 경계, 경로별 리뷰어, 동료 리뷰 |
| 남긴 것 | 변경 제안·CI·계층 보호·계약 lockstep·TDD·커밋 규율·금지 목록 |

---

## 맺음 — 전환이 매끄러운 이유

```
협업:  경계 = 사람 사이       "A는 이 영역"
              │  (혼자가 되는 순간)
              ▼
개인:  경계 = 계층 사이       "이 계층은 함부로 안 바꿈"
```

처음부터 경계를 *사람*뿐 아니라 *구조*에도 걸어두었기 때문에,
협업이 끝나도 방법론이 붕괴하지 않는다.

> **규율을 파일과 자동화에 걸어라. 그러면 사람이 셋이든 하나든 작동한다.**

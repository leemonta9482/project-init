# 00 · 방법론 원리 (스택 무관)

> 이 툴킷의 모든 규칙은 아래 5개 원리에서 파생됩니다.
> 원리를 이해하면 어떤 스택·팀에도 스스로 변형해 적용할 수 있습니다.

---

## 원리 1 — Governance-as-Code (규율을 파일로)

**규칙을 사람의 기억·구두 합의가 아니라 리포지토리 안의 파일로 둔다.**

- 파일은 읽히고, 실행되고, 차단한다. 기억은 그렇지 못하다.
- 새 멤버·새 AI·6개월 뒤의 자신이 **같은 파일**을 읽는다 → 단일 진실 공급원.

### 두 종류의 규율 파일

| 종류 | 예 | 성격 |
|------|-----|------|
| **규범 문서** | `CLAUDE.md`(루트/영역), 스타일 가이드 | 사람·AI가 읽는 원칙 |
| **자동 강제** | `CODEOWNERS`, CI 설정, pre-commit 훅 | 기계가 검사·차단 |

> 규범 문서는 *이유*를 주고, 자동 강제는 *집행*을 한다. 항상 **둘을 겹쳐라** —
> 문서만 있으면 안 지켜지고, 자동화만 있으면 왜 그런지 몰라 우회한다.

---

## 원리 2 — 경계를 구조에 걸어라 (사람이 아니라)

작업 경계에는 두 종류가 있다.

- **사회적 경계**: "이 사람이 이 영역을 담당" — 사람이 떠나면 무의미해짐.
- **구조적 경계**: "이 계층은 함부로 안 바꿈" — 사람 수와 무관하게 코드 품질을 지킴.

**둘 다 걸어라.** 그러면:

- 팀이 있을 때 → 사회적 경계(CODEOWNERS)가 리뷰를 배정.
- 팀이 사라져도 → 구조적 경계(고비용 계층 보호)가 그대로 남음.

> 규율을 "누가 감시하느냐"에만 걸면 감시자가 사라질 때 함께 무너진다.
> "무엇을 지키느냐"에도 걸어야 혼자가 되어도 유지된다.

---

## 원리 3 — 다층 게이트 (한 곳이 놓쳐도 다음이 잡는다)

품질은 한 번에 잡지 않는다. **서로 다른 시점에 서로 다른 실수**를 잡는다.

```
[1] 커밋 순간        [2] 변경 제안(MR/PR)     [3] 통합(머지)
pre-commit 훅   →    CI 파이프라인        →   배포 파이프라인
로컬·즉시            원격·필수 통과            자동·재현 가능
비밀키/포맷 차단      lint·test·build         스키마 적용·릴리스
```

- 각 층은 **다른 계급의 실수**를 잡는다: 훅=위생, CI=정합성, 배포=릴리스 안전.
- 한 층에 모든 걸 몰면 그 층이 느려지고 우회 유혹이 생긴다.

---

## 원리 4 — 계획 우선 (설계가 커밋으로 남는다)

바로 코딩하지 않는다. **문서를 먼저 커밋**한다.

```
spec (왜·무엇)  →  plan (작업지시서, 작업 단위로 쪼갬)  →  구현 (계획대로)
```

- **spec**: 목표·비목표·제약. "무엇을 왜."
- **plan**: 파일·인터페이스·실패테스트·구현·커밋까지 명시한 작업 단위(Task) 목록.
- 계획이 리포에 커밋으로 남아, 구현이 표류하지 않고 리뷰가 계획 대비 가능해진다.

> 예외(trivial): 오타·문서·한 줄 수정은 spec/plan 생략 가능. 단 **변경 제안(MR) 자체는 유지**.

---

## 원리 5 — 계약 변경은 순서를 탄다 (Lockstep)

여러 부분이 공유하는 **계약**(DB 스키마, 공개 API, 메시지 포맷)을 바꿀 때:

> **계약을 먼저 배포하고, 그 계약에 의존하는 코드를 나중에 배포한다.**

- 순서를 바꾸면 "아직 없는 계약"을 참조하는 코드가 배포돼 런타임 오류(예: 500).
- 그래서 **계약 변경과 코드 변경을 같은 변경 제안에 섞지 않는다** — 분리해 순서를 강제.

일반화:

| 계약물 | 먼저 배포할 것 | 나중에 배포할 것 |
|--------|---------------|------------------|
| DB 스키마 | 마이그레이션 | 그 컬럼/테이블 쓰는 코드 |
| 공개 API | 서버(신규 필드 additive) | 그 필드 쓰는 클라이언트 |
| 메시지 큐 포맷 | consumer(둘 다 수용) | producer(신규 포맷 발행) |

## 다섯 원리의 상호작용

```
        ┌─────────────────────────────────────────┐
        │  원리1: 규율을 파일로 (Governance-as-Code) │  ← 토대
        └─────────────────────────────────────────┘
             │              │               │
      ┌──────▼─────┐  ┌─────▼──────┐  ┌─────▼──────┐
      │ 원리2 경계  │  │ 원리3 게이트│  │ 원리4 계획  │
      │ (구조에)   │  │ (다층)     │  │ (spec/plan)│
      └────────────┘  └────────────┘  └────────────┘
                            │
                    ┌───────▼────────┐
                    │ 원리5 Lockstep  │  ← 계약 변경 안전
                    └────────────────┘
```

이 다섯 개가 협업 모드(`01`)와 개인 모드(`02`) 양쪽을 관통합니다.
두 모드의 차이는 **원리2(경계)와 게이트의 승인 방식**에서만 갈립니다.
